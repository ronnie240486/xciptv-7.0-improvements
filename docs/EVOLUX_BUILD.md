# Build Evolux — versão de teste

## Alterações aplicadas

A marca exibida ao usuário foi alterada de `XCIPTV` para `Evolux` em `@string/app_name`. O ícone do launcher e os principais recursos visuais de marca foram substituídos pelo símbolo Evolux original, preparado em variantes para as densidades Android e para o ícone adaptativo.

O package interno permanece `com.nathnetwork.xciptv` nesta primeira build. Essa decisão reduz o risco de quebrar referências internas recuperadas do APK, mas significa que esta versão não deve ser tratada como uma migração definitiva de identidade técnica. A próxima etapa pode alterar o applicationId/package com uma refatoração completa de nomes, referências Smali e configuração de distribuição.

A keystore de desenvolvimento **não é versionada**. O APK foi validado por teste de integridade ZIP e assinatura v1/v2/v3. A build final inclui as sete bibliotecas nativas `arm64-v8a`, incluindo `libnative-lib.so`, `libffmpeg.so`, `libffmpegJNI.so`, `libvlc.so`, `libvlcjni.so`, `libavresample.so` e `libc++_shared.so`. Também foi confirmada a presença de `app_name=Evolux` e das variantes de ícone. No `LoginActivity`, as comparações de `login_type`, `portal`, `btn_signup`, `btn_login_settings` e `Config.f21195b` foram tornadas null-safe; `mac` agora usa string vazia como fallback antes de `toUpperCase()`. Em `LoginActivity.o()`, `ORT_WHICH_PANEL` usa `xtreamcodes` quando a leitura retorna nulo e `login_type` usa `login` como fallback. No `onResume`, a preferência `language` usa `pt` como fallback antes da construção de `Locale`. A apresentação inicial agora usa a imagem familiar fornecida como fundo, o logo Evolux em estilo 3D com movimento suave e o texto `Evolux Player` revelado em efeito de máquina de escrever; o áudio original foi preservado. O recurso `bg2` agora usa a imagem familiar fornecida como fundo padrão 16:9; ele permanece um recurso fallback, podendo ser substituído por uma atualização do painel. As cores globais de fundo continuam pretas para as telas que não usam imagem. O ícone foi refinado para um mark circular mais simples e transparente.

> Esta é uma build de teste derivada de código decompilado. O erro de `libnative-lib.so` e os NullPointerExceptions reportados no fluxo inicial do LoginActivity foram corrigidos na embalagem/bytecode, incluindo as ocorrências apontadas em `onCreate(SourceFile:616)`, `o(SourceFile:108)` e `onResume(SourceFile:64)`. A aplicação ainda não foi executada novamente em um dispositivo ou emulador nesta sessão; a validação funcional em runtime continua necessária, especialmente para confirmar a apresentação visual no aparelho. A checagem nativa que comparava o nome legado XCIPTV e chamava `finishAffinity()` foi removida do fluxo do SplashActivity, pois era a causa do fechamento após a primeira carga com a marca Evolux. A referência de contexto usada pelo restante do método foi preservada para evitar VerifyError de registrador indefinido. O método `SplashActivity.i()` agora usa a flag `S` como trava idempotente, impedindo que respostas assíncronas iniciem três instâncias sobrepostas de `LoginActivity`.

## Integração com o backend Rencia

O fluxo MAC/Rencia foi removido desta build de teste. A tela manual original foi restaurada com os campos de DNS/servidor (`ed_server`), usuário (`ed_username`), senha (`ed_password`) e botão de login (`btn_login`). Após a autenticação manual bem-sucedida, o aplicativo agora abre `CategoriesActivity` diretamente, sem relançar `SplashActivity`, evitando o retorno ao login causado pelas verificações legadas de licença. Nesta revisão, o fallback de idioma usa o registrador `v2` e a chamada `SharedPreferences.getString` também usa `v2`; o Context permanece em `v0`, eliminando o VerifyError que tratava uma String como Context. O carregamento nativo também foi desativado na própria `CategoriesActivity`.

A base também inclui a trava contra requisições duplicadas do bootstrap e mantém o package interno `com.nathnetwork.xciptv`. O identificador é estável entre reinstalações no mesmo perfil Android enquanto o `ANDROID_ID` não for alterado; ele não é o MAC físico do Wi‑Fi. O contrato completo do backend, incluindo heartbeat, notificações, failover, comandos remotos, aparência dinâmica e atualização, está registrado em `docs/BACKEND_CONTRACT.md`; esta build integra o fluxo inicial de validação e carregamento de listas, enquanto os ciclos de heartbeat/comandos permanecem como próxima etapa. A referência do cliente HTTP foi corrigida para a classe real `j/w` presente no dex; o nome `C2974w` era apenas o nome da decompilação Java. O retorno ao identificador após o carregamento foi corrigido gravando `login_type=login` e um perfil `PAINEL (XC)` ou `PAINEL (M3U)`, formato esperado pelo SplashActivity para reconhecer a sessão e permanecer em CategoriesActivity. Também foram desativadas na CategoriesActivity as duas saídas `finishAffinity()` herdadas da validação de marca, uma no método de preparação das categorias e outra no final do `onCreate`; elas encerravam a tela porque ainda comparavam a identidade XCIPTV antiga. O loop silencioso após a ativação pelo MAC foi corrigido no método `LoginActivity.k()`: o banco local agora recebe o usuário e a senha retornados pelo painel nos campos internos `T` e `U`, além do servidor `V`, em vez de ler os campos EditText antigos, que ficam ocultos na tela de identificador. Com isso, o `SplashActivity` consegue descriptografar a sessão local e não chama novamente `LoginActivity.i()`. Após o sucesso do login automático, o APK grava `rencia_authorized=true`; o método `SplashActivity.h()` usa esse estado para abrir `CategoriesActivity` diretamente e não chama mais a verificação legada `ApiIPTV.php?tag=licV4` para sessões autorizadas pelo painel. Na `CategoriesActivity`, as comparações de `time_format`, `btn_pr`, `btn_rec`, `hide_recording`, `btn_noti` e `btn_update` agora usam constantes não nulas como receptor de `equals`; isso evita o NPE observado em `onCreate(SourceFile:1002)` quando uma dessas preferências ainda não existe. O `onResume` da mesma atividade agora usa `pt` como fallback para a preferência `language` antes de construir `java.util.Locale`, corrigindo o NPE observado em `onResume(SourceFile:113)` antes da tela do MAC. Na build manual, o carregamento de `libnative-lib.so` foi desativado nos inicializadores estáticos de `SplashActivity`, `Methods` e `Config`: o `JNI_OnLoad` da biblioteca reconstruída abortava o processo com `JNI DETECTED ERROR: fid == null` durante `Runtime.loadLibrary`, antes de qualquer tela. `Config` inicializa seus campos com valores Java seguros para permitir a abertura do login manual. A biblioteca continua empacotada para preservar os recursos, mas não é carregada automaticamente nessa build.

## Instalação

Por ter sido assinado com uma chave de desenvolvimento diferente da assinatura do APK original, o Android pode impedir a atualização direta sobre a instalação original. Para teste, desinstale primeiro a versão anterior ou distribua a build com um applicationId diferente após a refatoração técnica.

Não reutilize a keystore de desenvolvimento em produção. Para publicação, gere ou use a keystore oficial da marca, configure um pipeline de assinatura protegido e valide a compatibilidade com os splits de ABI, idioma e densidade.
